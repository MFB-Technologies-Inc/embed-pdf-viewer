# Phase 3 Wave B: Interaction, Feedback, I18n and Actions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Typed C# capabilities for interaction (with feedback), i18n and actions, their platform services (a silent feedback default, an embedded-resource locale loader, a Jint script engine), and a guard that turns disposing a viewer from a kernel callback into an `InvalidOperationException` instead of a deadlock, so every wave B row of `platforms/dotnet/csharp-api-coverage.json` is ported.

**Architecture:** The wave A recipe (`03a-wave-a.md`, "Shared shape"): a public `*Capability` over the internal generated handle, hand-written public records with internal mappings in `Plugins/<Plugin>.Ffi.cs`, a `Get{Plugin}Async` accessor, streams through `PdfViewer.Stream` and `EventRelay`. New here: each foreign trait the app implements gets a public C# interface and an internal adapter implementing the generated trait. The adapter marks the thread with the viewer's identity while app code runs on the kernel thread, catches every exception the app throws and maps it to the trait's error (or logs it for a member with none), so app code never reaches the kernel as an unexpected callback error.

**Tech Stack:** .NET SDK 10.0.403 `net10.0`, xUnit 2.9.3, PublicApiAnalyzers 5.6.0, Jint 4.18.0 (BSD-2-Clause) with Acornima 1.9.1 (BSD-3-Clause), only in `EmbedPDF.Scripting.Jint`.

**Spec:** `docs/superpowers/plans/2026-11-20-dotnet-parity.md` (D3, D4 with the `Get{Plugin}Async` naming, D5, D8, "Phase 2 notes", the Phase 3 note on disposing from a kernel callback, "Phase 3 wave A notes"), `03a-wave-a.md`, the Swift sources `platforms/apple/EmbedPDF/Sources/EmbedPDF/Plugins/{Interaction,Feedback,ToolID,I18n,Actions,JavaScriptCoreEngine}.swift` and their tests `platforms/apple/EmbedPDF/Tests/EmbedPDFTests/{Interaction,Feedback,PointerLatency,I18n,Actions,JavaScriptCoreEngine}Tests.swift`.

## Decisions this plan makes

- **Jint lives in its own assembly.** `Jint.dll` for `net10.0` declares `IsAotCompatible`, and a library referencing it builds with 0 analyzer warnings, but a NativeAOT publish of a console app that runs one script (probe, 2026-11-20, linux-arm64) reports IL2026 from `Jint.Options.Apply` and `DefaultTypeConverter.BuildDelegate` (its CLR interop paths) plus IL2104 and IL3053 for the assembly. So `EmbedPDF.Viewer` keeps no Jint reference: the public `IScriptEngineFactory` lives there, and `JintScriptEngineFactory` ships in `platforms/dotnet/EmbedPDF.Scripting.Jint` (package `EmbedPDF.Scripting.Jint`, `IsAotCompatible`, PublicApiAnalyzers). Its consumers see Jint's publish warnings; the engine never enables the interop that raises them. Packing it into a release is Phase 6.
- **Recursion uses `Constraints.MaxExecutionStackCount`, not `LimitRecursion`.** The probe showed `LimitRecursion` throws `RecursionDepthOverflowException`, which script `try`/`catch` cannot see, while `MaxExecutionStackCount` raises `RangeError: Maximum call stack size exceeded` inside the script, which the prelude catches and Rust classifies as a budget failure (`crates/plugins/actions/src/ffi/sandbox.rs`, `is_resource_error`), as JavaScriptCore's does. With neither, deep recursion overflows the CLR stack and kills the process. Each realm runs on its own thread with a 16 MiB stack, so the depth (1,000 by default) never meets the kernel thread's smaller stack. *Changed after review:* `MaxExecutionStackCount` counts call expressions only, so recursion through a getter, a Proxy trap, a coercion or `new` still overflowed the stack and ended the process. The engine now sets `Constraints.StackOverflowGuard` alone (setting the count turns the guard off), which measures the stack on every entry into a script function; `MaxCallDepth` is gone and `ThreadStackBytes` is the bound.
- **Async-completion traits run app code off the kernel thread** (`Task.Run`), as Phase 2's `FetcherAdapter` does: `ILocaleLoader`, `IActionExecutor`, the document-verb operation. Disposing from them is safe, because the kernel thread is free. **Synchronous traits run app code on the kernel thread**, marked: `IInteractionHandler`, the tool permission, `IPlatformFeedback`, `IActionUiHandler`, `IActionSubmitHandler`, `IScriptEngineFactory`/`IScriptEngine`.
- Swift's completion objects (`LocaleLoadCompletion`, `ActionExecutorCompletion`, `DocumentVerbCompletion`) become `Task`-returning interface members, as `IDocumentFetcher` did in Phase 2. A one-method trait with no state (`ToolPermission`) is a `Func<bool>`.

## Review Focus

1. Disposing the viewer from a kernel callback: `Dispose()` inside an interaction handler throws `InvalidOperationException` at once rather than hanging, `DisposeAsync()` there starts disposal and its `ValueTask` throws `InvalidOperationException` only if blocked on before it completes, and the same calls from a thread-pool callback (locale loader) still dispose. Tasks 1 and 2 pin it.
2. An app callback that throws anything (not just `PdfException`) leaves the kernel working: a throwing `OnMove`, a throwing tool permission (reads `false`), a throwing feedback provider, a throwing UI handler (fails that dispatch with `HostError`, as the engine documents, and the next dispatch works; changed in execution, the first cut expected a failed node), a throwing script engine factory. Each owning task pins its trait with a follow-up call that succeeds.
3. A runaway, deeply recursive or memory-hungry script never takes the process down: timeout returns within 2 s, recursion is a `Budget` error, memory is reported and the realm is poisoned. Task 6 pins all three.
4. Scripts reach no CLR type: `typeof System`, `typeof importNamespace` and `typeof clrHelper` are `"undefined"`. Task 6 pins it.
5. A locale loader that returns `null`, throws synchronously, or faults its task fails the switch with `operation-failed` (keeping a `PdfException`'s code in the event) and never leaves `SetLocaleAsync` hanging. Task 4 pins it.
