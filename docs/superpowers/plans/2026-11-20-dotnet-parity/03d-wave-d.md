# Phase 3 Wave D: Annotation and Form Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Typed C# capabilities for annotation (with its selection, tools, drafts and threads sub-capabilities, every typed draft and patch, and the typed `AnnotationInfo` reads) and form, so every wave D row of `platforms/dotnet/csharp-api-coverage.json` (143: annotation 92, form 51) is ported or excluded.

**Architecture:** The wave A to C recipe (`03a-wave-a.md`, `03b-wave-b.md`, `03c-wave-c.md`): a public `*Capability` over the internal generated handle, hand-written public records with internal mappings in `Plugins/<Plugin>.Ffi.cs`, a `Get{Plugin}Async` accessor, streams through `PdfViewer.Stream` and `EventRelay`, foreign traits behind a public C# interface and an internal adapter that marks the kernel thread and contains every exception. Drafts and patches are `sealed record` types that write the engine's field bag (sorted keys) through an internal `FieldBag` over `System.Text.Json.Nodes`, with their leaf wire records (point, rect, quad, line points, destination, measure, number format) serialized by a source-generated `AnnotationJsonContext`; no reflection, so trim and AOT stay clean. The work is split so each task is testable alone and the wave can pause between tasks: vocabulary, then drafts and patches (offline JSON tests), then reads, then the capability (engine round trips), then form.

**Tech Stack:** .NET SDK 10.0.403 `net10.0`, xUnit 2.9.3, PublicApiAnalyzers 5.6.0, `System.Text.Json` source generation.

**Spec:** `docs/superpowers/plans/2026-11-20-dotnet-parity.md` (Global Constraints, D3, D4 with `Get{Plugin}Async` and the null-argument rule, D5, D8, "Phase 2 notes", the Phase 3 kernel-thread note, "Phase 3 wave A/B/C notes"), `03a-wave-a.md`, `03b-wave-b.md`, `03c-wave-c.md`, the Swift sources `platforms/apple/EmbedPDF/Sources/EmbedPDF/Plugins/{Annotation,AnnotationColor,AnnotationCommonFields,AnnotationDraft,AnnotationDraft+Boxes,AnnotationDraft+Markup,AnnotationDraft+Shapes,AnnotationInfo,AnnotationInfo+Kinds,AnnotationIntent,AnnotationPosition,AnnotationRichText,AnnotationSharedMembers,AnnotationSubtype,Form}.swift`, their tests under `platforms/apple/EmbedPDF/Tests/EmbedPDFTests/` (`AnnotationColorTests`, `AnnotationDraftTests`, `AnnotationKindDraftTests`, `AnnotationPatchDecodingTests`, `AnnotationInfoTests`, `AnnotationTests`, `FormTests`, `TypedOverloadTests`, the page case of `AttachmentTests`, the form case of `PluginSettingsTests`, the annotation and form cases of `IntegerSurfaceTests`), and the Rust serde the JSON must match (`crates/plugins/annotation/src/ffi/*.rs`, `crates/plugins/form/src/ffi.rs`, `crates/epdf-engine/src/features/annotation/write/prepare.rs`).

## Decisions this plan makes

- **`JsonNullable<T>` is Swift's `Nullable<Value>`.** `System.Nullable<T>` owns the name. `public readonly struct JsonNullable<T> : IEquatable<JsonNullable<T>> where T : notnull` with `static JsonNullable<T> Null`, `bool IsNull`, `T Value` (throws `InvalidOperationException` on null), `implicit operator JsonNullable<T>(T value)`. A member typed `JsonNullable<T>?` is left out when `null`, writes `null` when `JsonNullable<T>.Null`, and writes the value otherwise.
- **Colour is a value, not a literal.** `readonly record struct AnnotationColor(byte Red, byte Green, byte Blue)` with `static AnnotationColor Parse(string hex)` (`FormatException`), `static bool TryParse(string? hex, out AnnotationColor color)`, `string Hex`, `ToString() => Hex`. No implicit conversion from `string`: one that throws is a trap, and Swift's literal form traps too (`preconditionFailure`).
- **Open string sets** (`AnnotationSubtype`, `AnnotationIntent`, `AnnotationBorderStyleName`) are `readonly record struct X(string Value)` with static known values, as `ToolId` is. Swift's `AnnotationInfo.BorderStyle` is top-level `AnnotationBorderStyleName`, since a nested type and a property cannot share a name in C#.
- **Closed sets are enums** whose wire spelling lives in one internal table per enum (`AnnotationVocabulary`), refusing an undefined value with `invalid-input` from `ToJson` and from the create, update and defaults calls.
- **Drafts derive from `public abstract record AnnotationDraft`** (`public string ToJson()`, `internal abstract void Write(FieldBag bag)`, private protected constructor); **patches from `public abstract record AnnotationPatch`** (`public string ToJson()`). Each patch type implements `IAnnotationPatch<TSelf>` with `static abstract TSelf FromJson(string json)`, so `GetDefaultsAsync<TPatch>(ToolId)` decodes without reflection. Required draft members are positional (`new InkAnnotationDraft(inkList)`), optional ones `init`. `ToJson` throws `PdfException` `invalid-input` (`EncodingError`) for NaN or an infinity, as Swift's encoder does; `FromJson` throws `PdfException` `invalid-input` (`DecodingError`) for a declared key of the wrong shape. Output escapes with `JavaScriptEncoder.UnsafeRelaxedJsonEscaping` and sorts keys ordinally, matching Swift's `.sortedKeys, .withoutEscapingSlashes`.
- **Records hold lists as `IReadOnlyList<T>`**, compared by reference as every C# record does. The ported round-trip tests compare `ToJson()` output where Swift compared values.
- **Rich text and open maps use `JsonObject`.** `AnnotationRichText(IReadOnlyList<AnnotationRichTextParagraph> Paragraphs) { JsonObject? Body }`, `AnnotationRichTextParagraph(IReadOnlyList<AnnotationRichTextRun> Runs) { JsonObject? Properties }`, `AnnotationRichTextRun(string Text) { JsonObject? Style }`, `FromPlainText(string)`, `PlainText`. Writing deep-clones the nodes, so one value can go into several drafts.
- **`PdfMeasurement` and `PdfNumberFormat` are defined here** (with `MeasureOrigin`, `PdfNumberFraction`, `PdfLabelPosition`) as public twins of the generated measurement records, because line, polygon and polyline drafts carry `measure`. Wave E's measurement capability reuses them.
- **Reads:** `AnnotationInfo` is a sealed record built from the generated `AnnotationRecord`. `Details` is `AnnotationDetails?` (null when untyped); each kind's members are a sealed record deriving from `AnnotationDetails` (`AnnotationInkDetails`, `AnnotationHighlightDetails`, `AnnotationNoteDetails`, `AnnotationTextMarkupDetails`, `AnnotationStrikeoutDetails`, `AnnotationShapeDetails`, `AnnotationLineDetails`, `AnnotationPolygonDetails`, `AnnotationPolylineDetails`, `AnnotationFreeTextDetails`, `AnnotationCaretDetails`, `AnnotationStampDetails`, `AnnotationLinkDetails`, `AnnotationFileAttachmentDetails`, `AnnotationRedactionDetails`; `AnnotationAttachedFile`). Accessors `Ink`, `Highlight`, `Note`, `Underline`, `Squiggly`, `Strikeout`, `Square`, `Circle`, `Line`, `Polygon`, `Polyline`, `FreeText`, `Caret`, `Stamp`, `Link`, `FileAttachment`, `Redaction` read `Details` when `Subtype` matches. Timestamps are `DateTimeOffset?` beside `RawCreatedAt`/`RawModifiedAt`, through a port of Swift's parser. Swift's deprecated generated-record overloads (`get`, `list`, `selected`, `hitTest` returning `AnnotationRecord`) have no counterpart.
- **Generated annotation records get public twins** with the generated names (`AnnotationFilter`, `AnnotationBatchResult`, `AnnotationBatchFailure`, `AnnotationImportResult`, `AnnotationRefMapping`, `AnnotationEvent` union with `Created`/`Updated` carrying `AnnotationInfo`, `AnnotationResyncedPages`, `AnnotationThreadChange`, `AnnotationSelectionProps`, `AnnotationProperty`, `AnnotationTextFormat`, `AnnotationTool`, `AnnotationStampSource`, `AnnotationStampPlacement`, `AnnotationAttachmentFile`, `AnnotationTextEndAnchor`, `AnnotationPageQuads`, `AnnotationComment`, `AnnotationCommentThread`, `AnnotationCommentPermissions`, `AnnotationThreadStatus`, `AnnotationThreadDeleteResult`, `AnnotationThreadDeleteFailure`, `AnnotationFilePromptRequest`, `AnnotationPickedFile`, `AnnotationCreationDraft`). Bytes cross as `ReadOnlyMemory<byte>`; `AnnotationAttachmentFile.FromStreamAsync(Stream, string name, ...)` and `AnnotationStampSource.FromStreamAsync(Stream, ...)` read a stream.
- **File picker:** `public interface IAnnotationFilePicker { Task<AnnotationPickedFile?> PickAsync(AnnotationFilePromptRequest request); }`, called on the thread pool (a completion trait, wave B's rule); a throw answers no file and is logged. (Changed in execution: the first cut took a `CancellationToken`, but the engine's `pick` carries none, so the token would never fire.)
- **Form:** the generated form records get public twins with their generated names (`FormSettings`, `FormSettingsPatch`, `FormFieldRef` and so on). `uint` fields become `int`. `FormFocusTarget` is `public interface IFormFocusTarget { void Focus(bool select); }`, kernel thread, marked, a throw logged. The JSON escape hatches stay: `CreateAsync(string draftJson)`, `UpdateAsync(FormFieldRef, string patchJson)`, `AddWidgetAsync(FormFieldRef, string placementJson)`, `UpdateWidgetAsync(AnnotationRef, string patchJson)`.
- **Sub-capabilities are methods**, not properties: `GetSelection()`, `GetTools()`, `GetDrafts()`, `GetThreads()` on `AnnotationCapability`, each a new `IDisposable` over its own handle (Swift's computed properties create one per read too).
- **Link overloads from wave C:** `LinkCapability.ResolveAsync(AnnotationLinkTarget)`, `ActivateAsync(AnnotationLinkTarget)`, `GetLabelAsync(AnnotationLinkTarget)` write the target's JSON.
- **Exclusions.** Ten Rust members have no `ffi.rs` export and no Swift counterpart (added after the Swift port): annotation `get_shared`, `is_movable`, `can_duplicate`, `duplicate`, `when_remeasurable`, `stage_remeasure`, `selection_duplicate`, `selection_can_duplicate`; form `duplicate`, `duplicate_widgets`. Exporting them is a Rust change this plan may not make, so they are exclusions (`no-export`) and the report asks the user whether a later Swift and C# pass should export them.

## Review Focus

1. A `JsonNullable<T>?` member's three states reach the engine apart: left out keeps the value, `Null` clears it, a value sets it. Task 2's offline tests and Task 4's engine round trip pin it.
2. A draft holding NaN, an infinity or an undefined enum value never reaches the engine: `CreateAsync` faults with `invalid-input` and nothing is created. Tasks 2 and 4 pin it.
3. A `FromJson` of a tool's defaults that the patch cannot hold is `invalid-input`, while a key it doesn't declare is ignored. Task 2 and Task 4 (`GetDefaultsAsync<T>`) pin it.
4. A file picker that throws or disposes the viewer leaves the kernel working and the click declined. Task 4 pins it (`AThrowingPickerDeclinesAndTheViewerKeepsWorking`, `APickerMayDisposeTheViewer`).
5. Annotation and form streams and a registered picker or focus target that capture nothing leave an abandoned viewer collectable. Task 6 pins it in `LifetimeTests`.
