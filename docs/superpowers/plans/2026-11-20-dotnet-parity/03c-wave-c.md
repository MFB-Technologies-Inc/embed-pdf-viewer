## Decisions this plan makes

- **Stage destinations reuse `PageDestination`.** The generated `StagePageDestination` has the same cases and the same page space as `uniffi.epdf_ffi.PageDestination` (`crates/plugins/stage/src/ffi.rs:912-916`, `crates/epdf-ffi/src/annotation.rs:279-285`), so the public stage members take and return the wave A `PageDestination` instead of a twin.
- **Shared stage values keep Swift's names:** `Camera`, `ViewAnchor`, `PageFrameInsets`, `StageScrollMetrics` are `readonly record struct`s; `ZoomMode`, `StageAlign`, `StageDirection`, `StageSpreadMode`, `StageSizingMode` enums; `ZoomSpec`, `StageAlignValue` unions. Event records fold into their cases (wave A deviation).
- **JSON arguments are `string`.** `SetAppStateAsync(string json)` and `ExecuteAsync(..., string? argsJson)` take text, as Shell's props do. Swift takes `Data` to refuse bytes that are not UTF-8; the C# twin refuses a string with an unpaired surrogate (which UTF-8 encoding would turn into U+FFFD) with `("EncodingError", invalid-input)` before posting.
- **Link takes target JSON only.** Swift's `AnnotationLinkTarget` overloads of `resolve`, `activate` and `label` belong to the annotation drafts (wave D); wave D adds them.
- **`CommandHandler` is a sealed class from delegates**, as Swift's is from closures. `Run` (`Func<CommandContext, Task>`) runs on the thread pool, as Swift's runs in a `Task`, so disposing the viewer there is safe. `Enabled`, `Active`, `Visible`, `IconAccent` and `Locked` run on the kernel thread, marked; a throw reaches the kernel as `HostException.Failed`. C# exposes no `ICommandRunner`: a definition's hooks always come from its handler (Swift can also pass the generated runner with explicit hooks).
- **`IStandardCommandsPlatform`**: `SaveFile` on the kernel thread, marked, a throw logged; `CopyTextAsync`/`CopyImageAsync` return `Task` and run on the thread pool (wave B's rule for completion traits).
- **Exclusions.** `scene_key_builds`, `page_state_reads` (stage), `load_starts` (selection) and `resolve_command_text` (commands) are test and harness counters with no export (`crates/plugins/stage/src/controller.rs:277-288`, `crates/plugins/selection/src/controller.rs:1172-1177`, `crates/plugins/commands/src/controller.rs:806-810`); they become `internal-resource` exclusions. `wheel_by` has an export Swift never wrapped; C# ports it as `WheelByAsync`.

## Review Focus

1. A `CommandHandler` hook that throws (any exception, not only `PdfException`) leaves the registry working: a throwing `Enabled` makes `ResolveAsync` report the command disabled or absent rather than crash, and the next resolve of another command answers. Task 4 pins it.
2. `Dispose()` from a kernel-thread hook (`Enabled`, the initial-view provider, `SaveFile`) throws `InvalidOperationException` into the hook; from `Run` (thread pool) it disposes. Tasks 1 and 4 pin it.
3. The fire-and-forget stage calls (`SetCamera`, `PanBy`, `ScrollBy`, `ZoomAround`) after the document closes or the viewer is disposed do nothing and throw nothing, as `DispatchPointer` does; an undefined enum or a negative index there throws `PdfException` at once. Task 1 pins it.
4. A handler or provider whose delegates capture the capability does not keep an abandoned viewer alive, and live stage, selection, link and commands streams end when it is collected. Task 6 pins it in `LifetimeTests`.
5. Selection's `ReadTextAsync` cancelled mid-call surfaces `OperationCanceledException` and a later read still works. Task 2 pins it.
