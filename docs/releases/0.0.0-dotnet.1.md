## Breaking changes from 0.0.0-dotnet.0

The public API wasn't frozen in 0.0.0-dotnet.0, and these changes have no deprecation step ([`e3c57618e`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e3c57618e), [`f9bda565e`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/f9bda565e)).

`IFormFocusTarget.Focus(bool)` returns a `bool`: `false` when nothing will take the cursor, so it passes over the box. The interface gains `TakesCursor()`, asked each time the cursor is about to move, whose default implementation answers `true`; a target that answers `false`, such as a signature field nobody in the session can sign, is skipped by focus and Tab (upstream #1146). A target that throws from either is treated as answering `true`.

`AnnotationDraftsCapability.PreviewPlacementAsync` takes `double? displayRotation = null` before its `CancellationToken`. A call that passes the token by position has to name it, and assemblies built against 0.0.0-dotnet.0 need a rebuild.

Several positional records gain parameters, so constructing or deconstructing them breaks: `FormField` (`Purpose`, `Format`), `FormFillItem` (`Frame`, `Rotation`, `GroupId`, `CanFill`, `Required`, `Empty`, `Accent`), `FormWidgetHit` (`Frame`, `Rotation`), `FormFillControl.Toggle` (`InGroup`) and `FormFieldSettings` (`Tint`). `FormFieldPatchKey` has three new members, `Purpose`, `Format` and `GroupId`, and `FormEvent` two new records, `GroupsChanged` and `DesignGroupChanged`.

One change alters results: a field placed, created or copied without a group is in no group, whatever the session's own group is (upstream #1140, [`a88255b34`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/a88255b34)). Before, it took the session's group. Name the group in the draft, or set one with `SetDesignGroupAsync`.

## Added

Form groups on `FormCapability`: `SetGroupsAsync` names the document's groups (`FormGroupInput`, with an optional label and CSS color), `GetGroupsAsync` lists them as `FormGroup`s, `SetDesignGroupAsync` and `GetDesignGroupAsync` pick the group fields placed with a tool go into, `MoveToGroupAsync` moves fields in or out as one undo step, `CanSetGroupAsync` says whether the session may, and `GetSelectedFieldsAsync` lists the fields whose widgets are selected in design mode. Groups are session state; nothing is written into the PDF. A fill item's `Accent` is its group's color and strength, which `FormFieldSettings.Tint` scales, and `AnnotationInfo.Accent` carries the same color on a lent widget.

Field purpose and format: `FormField.Purpose` and `.Format` read them, and `FormCreateFieldInput` and `FormFieldPatch` set them. `FormFieldFormat` is `Date` or `Time` with its pattern; `Other` is read only, and writing it is `InvalidInput` (upstream #1147).

Attaching UI to a field box: `GetWidgetAnchorAsync` answers a `FormWidgetAnchor` (page and bounds), and `IsWidgetFocusedAsync` whether the cursor is in it. `FormFillItem.Frame` is the box the contents are laid out in (upstream's `box`), `Rotation` the quarter turn between it and `Bounds`, and `CanFill`, `Required` and `Empty` describe the field (upstream #1138). `FormFillControl.Toggle.InGroup` is a radio button's `FormGroupPosition` in its group. Form fields read upright on a turned page, and `PreviewPlacementAsync`'s `displayRotation` makes the drag preview match what the commit places (upstream #1118).

A signature mark can be a PNG or a JPEG, where only a one-page PDF worked before, and clearing a signature field takes its mark out (upstream #1145, [`b04fefba9`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/b04fefba9)).

`scripts/check-api-coverage.py --platform csharp` now maps 889 members: 748 ported, 0 pending and 141 exclusions.

## Validation

The release train ran `.github/workflows/release-dotnet.yml` as for 0.0.0-dotnet.0: each RID's viewer host built on its own native runner, `runtime-pack` with `EmbedPDF.Viewer.Tests` and `EmbedPDF.Models.Tests` on `net10.0` and `net11.0`, the coverage check, `package.py validate-runtime` on every RID, and the `consumer` job on `linux-arm64`, `linux-x64`, `osx-arm64` and `win-x64`. `runtime-pack` checked that `EmbedPDF.Runtime.props` pins `0.0.0-engine.11ca75894cda26ea`, the tree's engine hash. The new `FormGroupsTests` cover the surface above. The three signature route tests were skipped, as before. The run's logs have the test counts.

## Known gaps

There's still no UI package, so there's no form controls UI either: an app draws its own controls over `GetWidgetAnchorAsync` and the fill items. The push-button icon calls and the page geometry read have no C# surface. The test suites ran on `linux-arm64` only, and NativeAOT was checked on the two Linux RIDs only, as in 0.0.0-dotnet.0. The public API still isn't frozen: everything is in `PublicAPI.Unshipped.txt`, so 0.0.0-dotnet.2 may change any of it without a deprecation step.
