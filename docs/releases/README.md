# Release notes

The release train (`.github/workflows/release-train.yml`) reads each release's notes from this directory, so they are written and committed before you dispatch it. The Swift package's notes are `<swift_version>.md` (for example `0.0.0-swift.8.md`) and the Rust viewer bundle's are `rust-viewer-<viewer_version>.md`, each named for its tag. The C# engine's tag ends in the first 12 characters of the commit the train builds, so it can't be named ahead of time, and its notes are a single `dotnet-engine.md` that every C# release reuses: edit it in place when that release changes. On a real run the preflight job stops the train before anything is published if one of the three files is missing. A dry run only warns.

Every release the train makes goes to this repo as a prerelease, the engine and runtime releases (`runtime-<sha>`, `runtime-payloads-<hash>`, `apple-engine-<hash>`) included. The publish jobs use the run's own `GITHUB_TOKEN` and wait for the `release` environment's required reviewer. Payloads and Apple engines published before the first train stay on `MFB-Technologies-Inc/embed-pdf-runtime`; until a train publishes new ones, a local `fetch:payload` needs `EPDF_PAYLOAD_REPO=MFB-Technologies-Inc/embed-pdf-runtime`.

The train also redeploys the hosted demo, `examples/rust-kernel-eval`, at https://embed-pdf-rust-kernel-eval.roan-util-cloudfare.workers.dev. `release-rust-viewer.yml` builds the site beside the viewer tarball, and after approval the train's `deploy-demo` job runs `wrangler deploy` with `examples/rust-kernel-eval/wrangler.jsonc`. It deploys on every real run, even when the viewer bundle is already released. It needs two repository secrets: `CLOUDFLARE_API_TOKEN`, an API token with the Workers Scripts: Edit permission on the Cloudflare account, and `CLOUDFLARE_ACCOUNT_ID`. They are repository secrets, not `release` environment secrets, because `approve` is the only job allowed an environment. A real run's preflight stops when either is missing. To deploy by hand, build the site (`pnpm bootstrap`, then `pnpm build`, in `examples/rust-kernel-eval`) and run `npx wrangler deploy` there.
