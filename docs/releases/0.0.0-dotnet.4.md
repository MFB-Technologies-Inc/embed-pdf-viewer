The C# viewer packages `EmbedPDF.Runtime`, `EmbedPDF`, `EmbedPDF.Models`, `EmbedPDF.Extensions.DependencyInjection` and `EmbedPDF.Scripting.Jint`, rebuilt with Rust 1.100.1 and otherwise unchanged from 0.0.0-dotnet.3 (upstream `cda9e82a4`, viewer 3.4.0). The feed, the assets and how to add them are as in `docs/releases/0.0.0-dotnet.1.md`.

```xml
<PackageReference Include="EmbedPDF" Version="0.0.0-dotnet.4" />
```

`EmbedPDF.Runtime` is `0.0.0-engine.1524e55c9d8cb1bf`, up from `0.0.0-engine.7dd0c2b9e60f92a1` ([`1910f8b69`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/1910f8b69)). The runtime fork is still `9472117ed`; the new hash comes from Rust 1.100.1 ([`104cf9fe6`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/104cf9fe6)), since `rust-toolchain.toml` is a hash input. `EmbedPDF` 0.0.0-dotnet.4 needs this runtime.

`EmbedPDF.Scripting.Jint` now depends on Jint 4.18.1, up from 4.18.0 ([`aeead1da9`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/aeead1da9)), so an app that references it resolves at least that Jint.

## Breaking changes from 0.0.0-dotnet.3

None. The public API is the same.
