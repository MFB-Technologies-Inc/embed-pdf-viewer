The API is unchanged from 0.0.0-android.4 (upstream `cda9e82a4`, viewer 3.4.0), and everything in `docs/releases/0.0.0-android.4.md` still applies except as below.

## Breaking changes from 0.0.0-android.4

The libraries are built with Kotlin 2.4.21, up from 2.2.21 ([`006e420f2`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/006e420f2)). Kotlin 2.4.21's standard library comes in through the POMs, and an app's Kotlin compiler has to be 2.3 or later to read the libraries' metadata; 0.0.0-android.4 needed 2.1.

`embedpdf` exposes newer libraries through its `api` dependencies: kotlinx-coroutines 1.11.0, up from 1.10.2 ([`5d223afc5`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/5d223afc5)), and kotlinx-serialization-json 1.13.0, up from 1.9.0 ([`1b005b7a4`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/1b005b7a4)). It also takes androidx.annotation 1.11.0, up from 1.8.1 ([`c6f1e202d`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/c6f1e202d)). Gradle resolves the app to at least these versions.

`compileSdk` 36 and the Compose BOM ceiling (2026.06.01) are unchanged. lifecycle stays on 2.9.4, because 2.11 needs `compileSdk` 37 (#59).
