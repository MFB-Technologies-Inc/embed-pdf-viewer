The five `com.embedpdf` Maven artifacts (`embedpdf-bindings`, `embedpdf`, `embedpdf-javascript`, `embedpdf-models` and `embedpdf-compose`), with two engine fixes on top of 0.0.0-android.2. Everything in `docs/releases/0.0.0-android.2.md` still applies, including its breaking changes from 0.0.0-android.1.

Gradle: `implementation("com.embedpdf:embedpdf-compose:0.0.0-android.3")`

The engine is `embedpdf-bindings` at `0.0.0-engine.64cf9e896bdd28bc`, up from `0.0.0-engine.c82c25262037ff9c` ([`54fa68a14`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/54fa68a14)), still linked with the runtime fork's slices at `9472117ed`. The release carries `embedpdf-android-maven-0.0.0-android.3.zip` and its `.sha256`, and the artifacts go to the GitHub Packages Maven registry as before.

## Fixed

The JavaScript sandbox chain gap from 0.0.0-android.1 is fixed: `btn-chain` in `action_buttons_form.pdf` now logs "AB", as TypeScript does. The engine read every `ResetForm` as having no `/Fields`, which resets the whole form and dropped the first script's write; `Hide` targets and `SubmitForm` payloads were missing for the same reason (#39, [`6b71b4243`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/6b71b4243)).

`StageSettingsPatch`'s `turnGestures` defaults to `null` like its other fields, so you can leave it out of the constructor ([`08cce28cd`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/08cce28cd)). Code that passed `null` still compiles.

## Validation

`.github/workflows/release-android.yml` ran as for 0.0.0-android.2. No emulator or device test runs in CI.

## Known gaps

As in 0.0.0-android.2, less the chain gap. The instrumented tests haven't run against this engine hash.
