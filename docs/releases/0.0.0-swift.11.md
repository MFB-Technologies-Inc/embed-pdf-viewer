The `EmbedPDF`, `EmbedPDFModels` and `EmbedPDFUI` libraries, caught up with upstream `embedpdf/embed-pdf-viewer` `9af4d9ee7` (viewer 3.4.0, [`d670a1cbf`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/d670a1cbf)). This tag is the commit the release train made to pin the repository-root `Package.swift` and `platforms/apple/EmbedPDF/Package.swift` to `apple-engine-ca2421677d81b1d9`, the engine it built in the same run, replacing `apple-engine-c55b85806b96c5b2`, which 0.0.0-swift.10 pinned. No local package path or engine environment flag is required.

SwiftPM: `.package(url: "https://github.com/MFB-Technologies-Inc/embed-pdf-viewer", exact: "0.0.0-swift.11")`

The engine is built from a new runtime fork commit, `9472117ed` (upstream runtime `7f399f838`), up from `af480d0ce` (upstream `f2ea75972`). Rust is still 1.100.0. The runtime renamed its three stamp drawing exports (`EPDFAnnot_GetStampDrawing`, `EPDFAnnot_SetStampDrawing`, `EPDFDoc_GetStampDrawings` became `EPDFAnnot_GetDrawing`, `EPDFAnnot_SetDrawing`, `EPDFDoc_GetDrawings`), and the `pdfium` crate followed ([`f8a124edc`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/f8a124edc), [`defe697f2`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/defe697f2)). No Swift name changed with it: the Swift API never named stamp drawings. The engine reads a page's glyphs 4,096 at a time through the runtime's new `EPDFText_GetPageGeometry` instead of one character per call ([`1f2411c1c`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/1f2411c1c)).

## Breaking changes from 0.0.0-swift.10

`FormFocusTarget.focus(select:)` answers a `Bool` ([`e3c57618e`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e3c57618e), [`d2d0a4386`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/d2d0a4386)). Every conformer has to return one: `false` when nothing will take the cursor, so it passes over the box. The protocol also gains `takesCursor()`, asked each time the cursor is about to move; `false` makes focus and Tab skip the field, which is what a signature field nobody in the session can sign wants (upstream #1146). An extension answers `true`, so a conformer that writes only `focus(select:)` keeps taking the cursor.

`AnnotationRecord`'s memberwise initializer takes a new `accent:` argument, and the generated form records grow members: `FormField` (`purpose`, `format`), `FormFillItem` (`frame`, `rotation`, `groupId`, `canFill`, `required`, `empty`, `accent`), `FormWidgetHit` (`frame`, `rotation`), the toggle control (`inGroup`) and `FormFieldSettings` (`tint`). Code that builds these values, usually test fixtures, needs the new arguments. `FormEvent` has two new cases, `.groupsChanged` and `.designGroupChanged`, and `FormFieldPatchKey` three, `.purpose`, `.format` and `.groupId`, so an exhaustive `switch` over either stops compiling.

One change alters results. A field placed, created or copied without a group is now in no group, whatever the session's own group is (upstream #1140, [`a88255b34`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/a88255b34)). Before, it took the session's group. An app that relied on that has to name the group in the draft, or set one with `setDesignGroup(_:)`.

## Added

Form groups ([`f7121c0df`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/f7121c0df), [`46be230a5`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/46be230a5), Swift in [`d2d0a4386`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/d2d0a4386)). `FormCapability.setGroups(_:)` names the document's groups with `FormGroupInput`s, a label and a CSS color each, and `groups()` lists them as `FormGroup`s. It's session state; nothing is written into the PDF. `setDesignGroup(_:)` picks the group fields placed with a tool go into, and `designGroup()` reads it. `moveToGroup(_:groupID:)` moves fields in or out as one undo step, `canSetGroup(_:)` says whether the session may, and `selectedFields()` lists the fields whose widgets are selected in design mode. A fill item carries its group's `accent` (a `RecordAccent`, color and strength), which `fields.tint` scales and `tint: 0` turns off, and a lent widget's `AnnotationInfo.accent` carries the same color while the annotation plugin edits it ([`ef50e73bf`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/ef50e73bf), [`cf2dee995`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/cf2dee995)).

Field purpose and format (upstream #1147, [`a88255b34`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/a88255b34)). `FormField.purpose` and `.format` read them, and `FormCreateFieldInput` and `FormFieldPatch` set them. A `FormFieldFormat` is `.date` or `.time` with its pattern; `.other` is read only, and writing it throws `invalid-input`. A format is written as the field's two format scripts, which show and parse a date by its pattern ([`7047385c5`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/7047385c5)).

Attaching UI to a field box (upstream #1138). `widgetAnchor(_:)` answers a `FormWidgetAnchor`, the page and rect a box stands in, and `isWidgetFocused(_:)` whether the cursor is in it. A fill item and a hit carry `frame`, the box the contents are laid out in (upstream's `box`), and `rotation`, the quarter turn between `frame` and `bounds`; a fill item also says whether the person `canFill` it and whether it's `required` or `empty`. A radio button's `inGroup` gives its place among its group's buttons, and a radio button's label now names its own option (upstream #1136).

Upright widgets on turned pages (upstream #1118). A field placed on a page shown turned reads upright there, the selection's rotate and reset turn lent widgets, and `AnnotationDraftsCapability.previewPlacement(tool:from:to:on:displayRotation:)` takes the page's display rotation so the drag preview matches what the commit places. `displayRotation` defaults to `nil`, which previews as before.

## Fixed

A signature mark can be a PNG or a JPEG, not only a one-page PDF (upstream #1145, [`b04fefba9`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/b04fefba9), [`54d2cba66`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/54d2cba66)). An image failed before. Clearing a signature field takes its mark out and draws the box again, and a marked widget's mark is fitted again when its box or turn changes ([`6770b00a8`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/6770b00a8)).

Tab and Shift+Tab treat a radio group as one stop even when another field sits between its buttons in the tab order (upstream #1149).

Text in a font the PDF names but doesn't embed draws in the registered fallback fonts; the fix is in the runtime (embedpdf/runtime#132, upstream #1159).

A `ResetForm` action of some fields resets only those fields. The engine read every `ResetForm` as having no `/Fields`, which resets the whole form, so the `btn-chain` button in `action_buttons_form.pdf` lost its first script's write; `Hide` targets and `SubmitForm` payloads were missing for the same reason (#39, [`6b71b4243`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/6b71b4243), [`866ad6fac`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/866ad6fac)). `StageSettingsPatch`'s `turnGestures` defaults to `nil` like its other fields, so you can leave it out ([`08cce28cd`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/08cce28cd)).

## Validation

The release train ran the packaged framework's tests on the bytes it published, on three runners of GitHub's `xcode-27` image under Xcode 27.2: an iPhone simulator on the newest iOS runtime matching the SDK, macOS arm64, and macOS x86_64 under Rosetta (`.github/workflows/release-apple.yml`). Each ran the `EmbedPDF-Package` scheme, which covers `EmbedPDFBindingsSmokeTests`, `EmbedPDFTests`, `EmbedPDFModelsTests` and `EmbedPDFUITests`, including the new `FormGroupsTests` ([`5a7abb9fe`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/5a7abb9fe)). The three signature route tests and the latency suites were skipped, as in 0.0.0-swift.10. The run's logs have the test counts.

## Known gaps

There's no form controls UI: `EmbedPDFUI` has no form layer, so an app draws its own controls over `widgetAnchor(_:)` and the fill items. The push-button icon calls (`EPDFAnnot_GetMKIcon` and the rest) and the page geometry read have no Swift surface. Printing is still not implemented: it needs a native `HostPrinter` (`platforms/apple/README.md`, "Audited API coverage"). The engine still has no x86_64 simulator slice. The deprecated aliases `PDFDocument` and `Annotation` are still present, and `PDFReaderView` still has no way to turn its search highlights off.
