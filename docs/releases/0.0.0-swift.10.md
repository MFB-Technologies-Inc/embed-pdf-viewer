The `EmbedPDF`, `EmbedPDFModels` and `EmbedPDFUI` libraries. This tag is the commit the release train made to pin the repository-root `Package.swift` and `platforms/apple/EmbedPDF/Package.swift` to the binary engine it built in the same run. That engine is a new `apple-engine-<hash>` prerelease on this repository, replacing `apple-engine-087f5a74ff6916ab`, which 0.0.0-swift.8 and 0.0.0-swift.9 pinned. The train rebuilt it because the annotation, form, redaction and signature crates changed since `1ba25cb9a`, the commit 0.0.0-swift.9 tags. No local package path or engine environment flag is required.

SwiftPM: `.package(url: "https://github.com/MFB-Technologies-Inc/embed-pdf-viewer", exact: "0.0.0-swift.10")`

The engine is built from the same runtime fork, `af480d0ce` (upstream runtime `f2ea75972`), now with Rust 1.100.0 instead of 1.98.0 ([`e4544c225`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e4544c225)). The only source change the new toolchain needed is a rename, `fetch_update` to `try_update`, in the engine's cancel token and the C API's byte budget ([`c2203ca2f`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/c2203ca2f)). The Rust exports Swift wraps below are new in this engine, and two engine changes alter results you could already get: the `markMatches` cancel and RSASSA-PSS verification, both described below. The test targets' `swift-custom-dump` floor moved from 1.3.0 to 1.7.3 ([`d83b5e20d`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/d83b5e20d)); the root manifest SwiftPM consumers resolve doesn't depend on it.

## Breaking changes from 0.0.0-swift.9

No existing call stops compiling. Two change behaviour:

- `PDFReaderView` draws the search's hits on every page with a `SearchHighlightOverlay`, under the text selection and your `pageOverlay` ([`edfd563a1`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/edfd563a1)). In 0.0.0-swift.9 it drew none, and `platforms/apple/README.md` told apps to compose one from `SearchModel.hits` in the page overlay. An app that did that now gets two highlights per hit and should drop its own. There is no switch to turn the built-in one off.
- `RedactionCapability.markMatches(_:on:)` honours task cancellation ([`bf0d8af2a`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/bf0d8af2a)). Before, the engine ignored the cancel token, so a cancelled task still ran the search and made every mark, which took more than 90 s for `"e"` over `report.pdf`. Now a cancel aborts the search or stops between marks, keeping the marks already made, and the call throws `operation-cancelled`. A cancel that lands before the search finds a match returns an empty array instead of throwing ([`b165ed8b0`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/b165ed8b0)).

## Added

Annotations can be copied and remeasured ([`14a376622`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/14a376622), Rust exports in [`5480d0afa`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/5480d0afa)). `AnnotationCapability.duplicate(_:options:)` copies a list of `AnnotationRef`s as one undo step and returns an `AnnotationDuplicateResult`; `AnnotationDuplicateOptions` puts the copies on another `page`, moves them by an `offset` in page points, or will `select` them. `canDuplicate(_:)` says whether a person may copy them, and `isMovable(_:)` whether an annotation moves at all, which is `false` for one that sits on text, such as a highlight. `AnnotationSelectionCapability.duplicate(offset:)` copies the selection beside it and selects the copies, with `canDuplicate()` beside it. `stageRemeasure(on:to:)` updates every measurement on a page to a new `PdfMeasurement` scale and returns an `AnnotationRemeasureReport` of what it updated, skipped (with an `AnnotationRemeasureSkipReason`) and failed; call `whenRemeasurable()` first, since before the annotations load it updates nothing.

Form fields can be copied too ([`4111577c7`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/4111577c7), Rust exports in [`ebf3fa761`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/ebf3fa761)). `FormCapability.duplicate(_:options:)` copies whole fields under new names (`email` becomes `email_2`), with their settings, scripts and widgets. `duplicateWidgets(_:options:)` copies widgets as a form designer's Duplicate does: a radio button's copy joins its group and any other widget's copy is a new field. Both take `FormDuplicateOptions`, whose `values` keeps the originals' values, and return a `FormDuplicateResult`. Every duplicate call answers `invalid-input` for an offset that is NaN or infinite rather than dropping it ([`c0c2cfb0a`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/c0c2cfb0a)).

For a reader you compose yourself, `SearchHighlightOverlay(model:visiblePage:info:color:activeColor:blendMode:)` draws one page's hits in a `StageReaderView` page overlay ([`b210a87fa`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/b210a87fa)). Its fills and blend mode come from `SearchModel.highlight`, the search plugin's `SearchHighlightSettings`, which defaults to `#ffd500` for a hit and `#ff9632` for the active one, multiplied with the page ([`4b9aacac8`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/4b9aacac8)). The cost is one more engine read on every `SearchModel` refresh, scrolls and zooms included. `StageVisiblePage.localPoint(_:info:)` maps a page-space point into a page overlay, the inverse of `pagePoint(_:info:)` ([`b210a87fa`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/b210a87fa)).

## Fixed

Signature validation no longer accepts an RSASSA-PSS signature whose value is at or past the key's modulus. `rsa` 0.9 verified `s + n` when it fit in the key's length; 0.10 refuses it, as OpenSSL does ([`56fdd0c79`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/56fdd0c79), pinned by a test in [`1ab489544`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/1ab489544)). RSA keys under 1024 bits still import, matching WebCrypto, although `rsa` 0.10 refuses them by default ([`84115762d`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/84115762d)).

## Validation

The release train ran the packaged framework's tests before it published the engine, on the bytes it published, on three runners of GitHub's `xcode-27` image under Xcode 27.2: an iPhone simulator on the newest iOS runtime matching the SDK, macOS arm64, and macOS x86_64 under Rosetta (`.github/workflows/release-apple.yml`). Each ran the `EmbedPDF-Package` scheme, which covers `EmbedPDFBindingsSmokeTests`, `EmbedPDFTests`, `EmbedPDFModelsTests` and `EmbedPDFUITests`, including the new `AnnotationDuplicateTests` and `SearchHighlightOverlayTests`. The train doesn't start the signature routes helper (`platforms/android/tests/signature-routes.mjs`), so the three tests that need it, `aGrantedTimestampThroughTheTimestampRoute`, `aLongTermFillThroughTheRevocationRoute` and `aCallWithoutAnAuthoritySendsNoQuery`, were skipped. They last ran in 0.0.0-swift.7's validation, before the `rsa` 0.10 update. The latency suites, which need `EMBEDPDF_LATENCY=1`, were skipped too. The run's logs have the test counts.

## Known gaps

Printing is still not implemented: it needs a native `HostPrinter` (`platforms/apple/README.md`, "Audited API coverage"). The engine still has no x86_64 simulator slice; the Apple slices are `ios-arm64`, `ios-sim-arm64`, `darwin-static-arm64` and `darwin-static-x64`. The deprecated aliases `PDFDocument` and `Annotation` are still present, with no removal release chosen. `PDFReaderView` has no way to turn its search highlights off.
