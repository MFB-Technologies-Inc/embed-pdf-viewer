The `EmbedPDF`, `EmbedPDFModels` and `EmbedPDFUI` libraries. This tag is the commit the release train made to pin the repository-root `Package.swift` and `platforms/apple/EmbedPDF/Package.swift` to the binary engine it built in the same run. That engine, `EmbedPDFBindings`, is now published on this repository as an `apple-engine-<hash>` prerelease; `0.0.0-swift.7`'s engine was on the separate runtime repository. No local package path or engine environment flag is required.

SwiftPM: `.package(url: "https://github.com/MFB-Technologies-Inc/embed-pdf-viewer", exact: "0.0.0-swift.8")`

The engine underneath behaves as it did in 0.0.0-swift.7. It's built from the same runtime fork, `af480d0ce` (upstream runtime `f2ea75972`), with the same Rust 1.98.0. The one Rust change since `f37adb447` converts PDFium's enum types at the FFI boundary so the Windows build compiles; no signature or result changes ([`884d91776`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/884d91776)). Everything else below is the Swift layer.

## Breaking changes from 0.0.0-swift.7

These need an edit, and none has a deprecated shim:

- `AnnotationInfo.Details` has 14 new cases: `underline`, `squiggly`, `strikeout`, `square`, `circle`, `line`, `polygon`, `polyline`, `freeText`, `caret`, `stamp`, `link`, `fileAttachment` and `redaction` ([`9741d9156`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/9741d9156)). A `switch` over it without `default` stops compiling. Annotations of those subtypes, which read as `.untyped` in 0.0.0-swift.7, now read as their own case, so code that handled them under `.untyped` has to move.
- `AnnotationInfo.Ink.borderStyle` is an `AnnotationInfo.BorderStyle` and `AnnotationInfo.Ink.intent` is an `AnnotationIntent?`, not `String` and `String?` ([`a93b2f840`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/a93b2f840)). Comparing with a string literal still compiles. Code that needs the `String` uses `.rawValue`. Interpolating `intent` now prints `Optional(ink-highlight)`, without the quotes it printed before.
- `AnnotationPatch` refines `Codable`, not just `Encodable`, so `defaults(for:as:)` can decode a tool's defaults into a patch ([`f4361c6b6`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/f4361c6b6)). Every patch in the package conforms. A type of your own that conforms to `AnnotationPatch` needs an `init(from:)`.
- `StageReaderView` is generic over its page overlay, `StageReaderView<PageOverlay: View>` ([`6676b16f3`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/6676b16f3)). `StageReaderView(model:)` still compiles. A stored property or return type spelled `StageReaderView` needs `StageReaderView<EmptyView>`, or `some View`.
- The observable models moved from `EmbedPDFUI` to the new `EmbedPDFModels` module: `AnnotationModel`, `AttachmentModel`, `HistoryModel`, `OutlineModel`, `SearchModel`, `StageReaderModel`, `TiledPageModel` and `ViewerModel` ([`e9fe43b91`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e9fe43b91)). `EmbedPDFUI` re-exports `EmbedPDFModels`, so `import EmbedPDFUI` still names all of them and no import has to change. Only a module-qualified name breaks: `EmbedPDFUI.StageReaderModel` is now `EmbedPDFModels.StageReaderModel`.

One rename keeps a shim. `PDFViewer.render(in:)` and `search(in:)` are deprecated for `render(for:)` and `search(for:)`, the spelling the other capability accessors use ([`28980326d`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/28980326d)). The old names survive at least this release. `platforms/apple/README.md` keeps the full table of deprecated spellings under "Moving from 0.0.0-swift.4".

## Added

`EmbedPDFModels` is a library product of its own, so a target can use the models without depending on the SwiftUI views ([`e9fe43b91`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e9fe43b91)).

The reader grows into something an app can drop in. `PDFReaderModel` and `PDFReaderView` are a one-call reader: it opens a document, asks for a password when the document needs one, and shows a `StageReaderView` under a `SearchBar` ([`e1c4b1445`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e1c4b1445)), and an app can add plugins to it ([`35479b19a`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/35479b19a)). `SearchBar` ([`be7550496`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/be7550496)) and `ThumbnailStrip` with its `ThumbnailModel` ([`134e053d5`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/134e053d5)) also work beside a reader you compose yourself. A `StageReaderModel` made with an `InteractionCapability` sends touches to the active tool, and made with a `LinkCapability` it activates the link under a tap and reports it on `linkActivations` ([`547071095`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/547071095)). `ToolModel` and `ToolPicker` mirror and switch the tools ([`d9c7b5f19`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/d9c7b5f19)).

For apps that draw over pages: `StageReaderView(model:pageOverlay:onLinkActivation:)` lays a view over each visible page and can hand it the drag ([`6676b16f3`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/6676b16f3)). `PageGeometry` converts points, rects and images between page and display space ([`df1853e0e`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/df1853e0e)), with one rotation type and CoreGraphics overloads ([`8f4c21084`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/8f4c21084)). `TextSelectionModel` orders and coalesces drag selection ([`932613543`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/932613543)) and `TextSelectionOverlay` draws it ([`425bc1a0b`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/425bc1a0b)). `RenderRevisions` reports per-page render invalidations outside the stage reader ([`fedfc5eb1`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/fedfc5eb1)).

Annotations are typed end to end. Every subtype the engine creates from a field bag has a typed draft and patch, stamps and file attachments have a patch, and `AnnotationInfo` reads typed members for every subtype but popup and widget, with a typed `blendMode` ([`9741d9156`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/9741d9156)). The members every kind shares are `AnnotationCommonFields` ([`f31dc8015`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/f31dc8015)); rich text is `AnnotationRichText` and a dimension's scale is a `PdfMeasurement` ([`686b8ba0a`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/686b8ba0a)). Typed overloads sit beside the JSON entry points ([`105648dba`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/105648dba)), `defaults(for:as:)` reads a tool's defaults as a typed patch ([`f4361c6b6`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/f4361c6b6)), and `MeasurementCapability.readout(_:)` takes an `AnnotationRef` ([`3824efc24`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/3824efc24)). `DocumentFetcher`, `DocumentFetchCompletion` and `DocumentFetchCancellation` are now exported from `EmbedPDF` ([`28980326d`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/28980326d)).

## Fixed

A model's `error` clears when the failed kind of call next succeeds, where it used to stay set ([`728f06744`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/728f06744)). The reader ends a pan the gesture system drops ([`678f7b13b`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/678f7b13b)), cancels an open pointer gesture before a tap ([`5415fcf01`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/5415fcf01)), and under long-press selection begins a pan after 10 points and no longer lets a tap cancel a zoom or a link's scroll ([`4d365f91c`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/4d365f91c), [`7fcf987ac`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/7fcf987ac)). A page overlay's mapping stays finite at a zero width ([`d6d180e7f`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/d6d180e7f)), and a reader without links no longer builds a page set on every camera event ([`44315a750`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/44315a750)).

## Validation

The release train ran the packaged framework's tests before it published the engine, on the bytes it published, on three runners of GitHub's `xcode-27` image under Xcode 27.2: an iPhone simulator on the newest iOS runtime matching the SDK, macOS arm64, and macOS x86_64 under Rosetta (`.github/workflows/release-apple.yml`). Each ran the `EmbedPDF-Package` scheme, which covers `EmbedPDFBindingsSmokeTests`, `EmbedPDFTests`, `EmbedPDFModelsTests` and `EmbedPDFUITests`. The train doesn't start the signature routes helper (`platforms/android/tests/signature-routes.mjs`), so the three tests that need it, `aGrantedTimestampThroughTheTimestampRoute`, `aLongTermFillThroughTheRevocationRoute` and `aCallWithoutAnAuthoritySendsNoQuery`, were skipped. They last passed in 0.0.0-swift.7's validation. The latency suites, which need `EMBEDPDF_LATENCY=1`, were skipped too. The run's logs have the test counts.

## Known gaps

Printing is still not implemented: it needs a native `HostPrinter` (`platforms/apple/README.md`, "Audited API coverage"). The engine still has no x86_64 simulator slice; the Apple slices are `ios-arm64`, `ios-sim-arm64`, `darwin-static-arm64` and `darwin-static-x64`. The deprecated aliases `PDFDocument` and `Annotation` are still present, with no removal release chosen.
