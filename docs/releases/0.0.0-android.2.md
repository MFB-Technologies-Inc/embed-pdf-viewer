## Breaking changes from 0.0.0-android.1

`FormFocusTarget` is the generated interface, and it changed ([`e3c57618e`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e3c57618e), [`81fac2a99`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/81fac2a99)). Every implementation now writes `takesCursor(): Boolean`, asked each time the cursor is about to move, and `focus(select: Boolean): Boolean`. There's no default: a Kotlin target must answer `true` from `takesCursor()` to keep taking the cursor. `false` makes focus and Tab skip the field, which is what a signature field nobody in the session can sign wants (upstream #1146), and `focus` answers `false` when nothing will take the cursor.

`AnnotationDraftsCapability.previewPlacement` takes `displayRotation: Double? = null` last. Kotlin callers compile unchanged, but the JVM signature moved (`embedpdf/api/embedpdf.api`), so code compiled against 0.0.0-android.1 needs a rebuild.

The generated records grow members, so constructing them or destructuring them by position breaks: `FormField` (`purpose`, `format`), `FormFillItem` (`frame`, `rotation`, `groupId`, `canFill`, `required`, `empty`, `accent`), `FormWidgetHit` (`frame`, `rotation`), the toggle control (`inGroup`), `FormFieldSettings` (`tint`) and `AnnotationRecord` (`accent`). `FormEvent` has two new subclasses, `GroupsChanged` and `DesignGroupChanged` (aliased `FormEventGroupsChanged` and `FormEventDesignGroupChanged`), and `FormFieldPatchKey` three new entries, `PURPOSE`, `FORMAT` and `GROUP_ID`, so an exhaustive `when` over either stops compiling.

One change alters results: a field placed, created or copied without a group is in no group, whatever the session's own group is (upstream #1140, [`a88255b34`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/a88255b34)). Before, it took the session's group. Name the group in the draft, or set one with `setDesignGroup`.

## Added

Form groups on `FormCapability`: `setGroups` names the document's groups (`FormGroupInput`, with a label and CSS color), `groups` lists them as `FormGroup`s, `setDesignGroup` and `designGroup` pick the group fields placed with a tool go into, `moveToGroup` moves fields in or out as one undo step, `canSetGroup` says whether the session may, and `selectedFields` lists the fields whose widgets are selected in design mode. Groups are session state; nothing is written into the PDF. A fill item's `accent` (`RecordAccent`) is its group's color and strength, which `fields.tint` scales, and `AnnotationInfo.accent` carries the same color on a lent widget.

Field purpose and format: `FormField.purpose` and `.format` read them, and the create input and patch set them. `FormFieldFormat` is `FormFieldFormatDate` or `FormFieldFormatTime` with its pattern; `FormFieldFormatOther` is read only, and writing it throws `invalid-input` (upstream #1147).

Attaching UI to a field box: `widgetAnchor` answers a `FormWidgetAnchor` (page and bounds), and `isWidgetFocused` whether the cursor is in it. A fill item's `frame` is the box the contents are laid out in (upstream's `box`), `rotation` the quarter turn between it and `bounds`, and `canFill`, `required` and `empty` describe the field (upstream #1138). A radio button's `inGroup` is its `FormGroupPosition`. Form fields read upright on a turned page, and `previewPlacement`'s `displayRotation` makes the drag preview match what the commit places (upstream #1118).

A signature mark can be a PNG or a JPEG, where only a one-page PDF worked before, and clearing a signature field takes its mark out (upstream #1145, [`b04fefba9`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/b04fefba9)).

`platforms/android/kotlin-api-coverage.json` maps 746 of the 882 members the Swift manifest lists and excludes the other 136; none is pending.

## Validation

`.github/workflows/release-android.yml` ran as for 0.0.0-android.1: the pin check against `android-engine-hash.sh`, `build-aar.sh test` with the 16 KB checks, `apiCheck`, the JVM unit tests of the six modules including the new `FormGroupsTest`, the Kotlin coverage check, `android-consumer.sh`, and the demo built once more from the zip. No emulator or device test runs in CI, and Android lint isn't part of the release.

## Known gaps

The instrumented tests, with a new `DeviceViewerTest` case for groups, purpose, format, a turned widget and a target that declines the cursor, last ran on 2026-11-27, by hand, on one `Pixel_4` emulator with the arm64 16 KB page image: 17 of 17 passed. That run used the same engine hash, `c82c25262037ff9c`, but libraries built locally from locally built `9472117ed` slices, not the bytes this release ships. Nothing has run on physical hardware, and the `x86_64` engine has never been executed. The JavaScript sandbox chain gap from 0.0.0-android.1 (`btn-chain` in `action_buttons_form.pdf` logs "B" where TypeScript logs "AB") is not fixed.

There's no form controls UI: `embedpdf-compose` has no form layer, so an app draws its own controls over `widgetAnchor` and the fill items. The push-button icon calls and the page geometry read have no Kotlin surface. Printing is not implemented.
