The runtime fork is still `9472117ed`; the new hash comes from the Rust engine change below. `EmbedPDF` 0.0.0-dotnet.2 needs this runtime.

## Fixed

A `ResetForm` action of some fields resets only those fields. The engine read every `ResetForm` as having no `/Fields`, which resets the whole form, so a chained JavaScript button lost its first script's write; `Hide` targets and `SubmitForm` payloads were missing for the same reason (#39, [`6b71b4243`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/6b71b4243)).

Two flaky model tests now wait on a settled model instead of a time window ([`e3d6e7fbc`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/e3d6e7fbc)). Nothing shipped changed with it.

## Validation

`.github/workflows/release-dotnet.yml` ran as for 0.0.0-dotnet.1, on .NET 10 and 11. The run's logs have the test counts.

## Known gaps

As in 0.0.0-dotnet.1. `ToolModelTests.AnActivationCompletesWhileStateRevisionsKeepArriving` is timing based and failed once in 30 local runs; it hasn't failed in CI.
