The `EmbedPDF`, `EmbedPDFModels` and `EmbedPDFUI` libraries, unchanged from 0.0.0-swift.8. Nothing under `platforms/apple` or `crates` has changed since `aeb58f8ff`, the commit 0.0.0-swift.8 tags, and both manifests still pin the same binary engine, `apple-engine-087f5a74ff6916ab`. The train didn't rebuild that engine, so this tag names the commit it was dispatched on, not a new pin commit. Every commit since 0.0.0-swift.8 changes CI, the C# test project or the perf harness. This release exists because the train that redeploys the hosted demo publishes a Swift tag too.

SwiftPM: `.package(url: "https://github.com/MFB-Technologies-Inc/embed-pdf-viewer", exact: "0.0.0-swift.9")`

Moving from 0.0.0-swift.8 needs no code change. The breaking changes, additions and fixes since 0.0.0-swift.7 are in [0.0.0-swift.8's notes](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/releases/tag/0.0.0-swift.8).

## Validation

None beyond 0.0.0-swift.8's. With the engine already released, the train skipped the Apple build and test jobs, and 0.0.0-swift.8's runs are the last time the packaged framework's tests ran on these bytes.

## Known gaps

The same as 0.0.0-swift.8. Printing is still not implemented: it needs a native `HostPrinter` (`platforms/apple/README.md`, "Audited API coverage"). The engine still has no x86_64 simulator slice. The deprecated aliases `PDFDocument` and `Annotation` are still present, with no removal release chosen.
