## Breaking changes from 0.0.0-dotnet.2

Three positional records gain a parameter, so constructing or deconstructing them breaks: `FormField` (`ForAnyone`), `FormWidgetRecord` (`Layout`) and `FormFieldDetail.Pushbutton` (`HasImage`), which had none ([`68ab7e46d`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/68ab7e46d)). The inputs gain `init` properties instead, which breaks nothing: `ForAnyone` and `Layout` on `FormCreateFieldInput`, `Layout` on `FormWidgetPlacement`, `ForAnyone` on `FormFieldPatch`.

`filledBy`, `filledByName` and `filledAt` in `FormField.FieldsJson` now always read `null` (upstream #1162). The engine no longer writes who filled a field into the PDF, and it ignores what an older file holds. No C# property ever typed them, so nothing stops compiling; code that parsed them out of the JSON gets `null`.

## Added

Fields anyone fills in (upstream #1163, [`db41381cb`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/db41381cb)). `FormField.ForAnyone` reads it, and `FormCreateFieldInput` and `FormFieldPatch` set it. Any signer may fill such a field, whatever its group, and a signing that names no lock locks every anyone field that holds a value. A field in a group, or a signature field, can't be for anyone: `InvalidInput`.

Push buttons that hold a picture (upstream #1165, [`8ed1f4f77`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/8ed1f4f77)). `FormCapability.SetButtonImageAsync(field, image)` puts a PNG, a JPEG or a one-page PDF in every widget of a push button, fitted whole inside each widget's border, and `null` takes it out. It returns a `FormFieldUpdateResult`. `FormFieldDetail.Pushbutton.HasImage` says whether a button holds one. A widget's `FormWidgetLayout` (`Caption`, `Image`, `CaptionBelow`, `CaptionAbove`, `CaptionRight`, `CaptionLeft` or `CaptionOver`) says how caption and picture sit, read from `FormWidgetRecord.Layout` and set on create, placement and `UpdateWidgetAsync`. The PDF stores a picture once however many buttons show it, sharing the store signature marks and stamps use.

`SetButtonImageAsync` goes straight to the engine as one change, outside the history's undo, so an undo after it steps back over the change before it, not the picture ([`064026d17`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/064026d17)). It throws `PermissionDenied` for a field a signature locked or the session may not fill ([`1c42006dc`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/1c42006dc)).

## Fixed

Filling a field or drawing a mark keeps earlier signatures valid (upstream #1162, [`fee9339ec`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/fee9339ec)). A fill wrote who filled the field into its `/EMBD_Metadata`, and a mark recorded its fit on the widget; a strict reader took either change, to an object an earlier signature covers, as a modification after signing. Neither is written now.

A new appearance on a signature field nobody signed no longer marks an earlier signature as broken (upstream #1161, [`dad7474af`](https://github.com/MFB-Technologies-Inc/embed-pdf-viewer/commit/dad7474af)).
